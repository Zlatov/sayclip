# Этапы разработки sayclip

> «Скажи — попадёт в буфер обмена.»

Каждый этап — маленький и самостоятельно тестируемый. Проверка всегда
проходит в роли конечного пользователя: человека, который ничего не знает
о внутренностях, просто ставит пакет и пробует им пользоваться.

Отличие рабочего процесса от debash: **git-коммиты, push и npm-публикацию
делает пользователь сам**, вручную, на каждом этапе. Ассистент готовит код
и описывает, что и как проверить, но не выполняет `git commit`/`git push`/
`npm publish` за пользователя.

---

## Хотелки (собрано до разбивки на этапы)

* push-to-talk — зажал хоткей, говоришь, отпустил — не toggle;
* запуск как демон из консоли: `sayclip start` / `sayclip stop`, либо
  просто `sayclip` — чтобы видеть лог в foreground;
* возможность добавить демон в автостарт системы;
* `sayclip reconfig` (или `--reconfig`) — перенастройка без переустановки;
* переключение локальной модели whisper (список моделей — например, через
  `ls` по заданной директории);
* переключение языка распознавания (в debash язык зашит намертво — здесь
  должен быть настраиваемым);
* возможность задать базовый промт для Whisper (initial prompt — влияет на
  словарь/стиль распознавания);
* результат транскрибации сразу попадает в буфер обмена;
* уведомление пользователя о результате/ошибке/отмене — на Linux
  `notify-send`, на Windows — toast/трей (конкретный механизм решить на
  соответствующем этапе);
* Linux — основная платформа, Windows — обязательна, но вторична по
  приоритету;
* транскрибация — только локальный whisper по пути к бинарнику/модели,
  без поднятия HTTP API (как в debash).

---

## Открытые решения (зафиксировано)

* **Имя пакета:** `sayclip` — свободно на npm (проверено 2026-08-20),
  займём место при первой публикации.
* **Push-to-talk:** честный hold-режим (`keydown` → запись, `keyup` →
  стоп) через `uiohook-napi`, не bracket-toggle.
* **Репозиторий:** публичный (как debash).
* **Лицензия:** MIT (как в debash).
* **Git/npm:** репозиторий, коммиты, push и публикацию выполняет
  пользователь сам. Порядок релизного цикла: edit code → `git commit`
  (чистое дерево обязательно) → `npm version patch` (сам коммитит и
  тегирует версию, но не пушит) → `git push --follow-tags` → `npm
  publish`.

## Этап 0 — Скелет CLI

Node.js проект, `package.json`, точка входа `bin/sayclip`, при запуске без
аргументов печатает заголовок/версию и ничего не падает.

**Тест:** `node bin/sayclip.js` → видно шапку, процесс не падает.

---

## Этап 1 — Инфраструктура публикации

`package.json`: `name: sayclip`, `bin`, `license`, `files`, минимальный
README для npm-страницы. Git-репозиторий, первый коммит, публикация первой
версии — всё вручную, пользователем.

**Тест:** после `npm install -g sayclip` — команда `sayclip` доступна
глобально, печатает ту же шапку, что и на этапе 0.

---

## Этап 2 — Локальная транскрибация по готовому файлу

Конфиг с путём к whisper-бинарнику и модели (по аналогии с debash — без
HTTP API). Команда вида `sayclip transcribe <файл.wav>` — прогоняет уже
готовый аудиофайл через whisper, печатает текст в терминал. Хоткея и записи
микрофона ещё нет — проверяем только сам pipeline транскрибации.

**Тест:** заранее записанный `.wav` с русской/английской речью →
`sayclip transcribe test.wav` → в терминале корректный текст.

---

## Этап 3 — Запись микрофона + push-to-talk хоткей (Linux)

`uiohook-napi` слушает глобальный хоткей, различая `keydown`/`keyup` (см.
открытое решение выше). Пока клавиша зажата — идёт запись с микрофона во
временный `.wav`, по отпусканию — файл уходит в whisper (как на этапе 2).

**Тест:** зажал хоткей, сказал фразу, отпустил → в терминале лога виден
распознанный текст.

---

## Этап 4 — Буфер обмена и уведомления (Linux)

Результат транскрибации копируется в буфер обмена (`xclip`/`xsel`/
`wl-copy` в зависимости от сессии). Уведомление об успехе/ошибке через
`notify-send`.

**Тест:** зажал хоткей → сказал фразу → отпустил → всплыло уведомление,
`Ctrl+V` в любом текстовом поле вставляет ровно то, что было сказано.

---

## Этап 5 — Демон-обвязка

`sayclip start` (фон) / `sayclip stop` / просто `sayclip` (foreground с
логом). Инструкция/скрипт для добавления в автостарт системы (systemd
user unit для Linux).

**Тест:** `sayclip start`, перезапуск сессии/системы с автостартом →
демон снова поднят без ручного запуска.

---

## Этап 6 — reconfig и настройки

`sayclip reconfig` — интерактивная перенастройка: путь к whisper/модели,
список доступных моделей (сканирование директории), язык распознавания,
базовый промт для Whisper.

**Тест:** `sayclip reconfig` → меняешь язык и модель → следующая
транскрибация уже использует новые настройки, без правки конфига руками.

---

## Этап 7 — README и релиз MVP (Linux)

`README.md` по образцу debash (О приложении / Системные требования /
Установка / Настройка / Использование / Зависимости / Лицензия), на

**Тест:** `npm pack --dry-run` — в тарболе есть `README.md`, `bin/`,
`src/`, `contrib/`; дальше релизный цикл как обычно (пользователь сам).

## Мелкие доработки (пост-релиз)

Найдены при реальном тестировании на второй машине (после Этапа 7,
v0.1.3 → v0.1.4), не отдельные этапы плана.

* [x] Выходной файл whisper (`-otxt`) на другой сборке whisper.cpp
  писался не туда, куда мы ожидали читать — `ENOENT` при чтении
  `<wav>.txt`. Починено: `transcribe.js` теперь явно задаёт `-of
  <wavPath>`, не полагаясь на поведение бинарника по умолчанию.
* [x] Очень короткое (случайное) зажатие хоткея → whisper не успевает
  дать вообще ничего → тот же `ENOENT`, пугающая ошибка на ровном
  месте. Починено: `listen.js` теперь пропускает транскрибацию, если
  хоткей был зажат меньше `MIN_RECORDING_MS` (400мс), тихо печатает
  `(too short, skipped)`.
* Отдельно всплыла классическая галлюцинация Whisper на тишине —
  «Редактор субтитров Н.Закомолдина Корректор В.Сухиашвили» (Whisper
  так реагирует на пустое аудио на русском). Причина оказалась не в
  коде: микрофон физически остался на другой машине при переключении
  KVM-свитчем (клавиатура/мышь/монитор переключились, микрофон — нет).

## Этап 8 — Windows-порт + трей-иконка статуса

Написано за один заход без доступа к живой Windows-машине — код готов,
но **не проверен на Windows**, только там, где можно было проверить
независимо от платформы (Linux).

* Запись — `record.js`: `arecord` (Linux, как раньше) / `ffmpeg -f dshow`
  (Windows). Имя микрофона на Windows не автодетектится (парсинг вывода
  `ffmpeg -list_devices` слишком хрупкий, чтобы городить его вслепую) —
  спрашивается один раз (`recordingDevice` в конфиге, как и путь к
  whisper), команда для поиска имени печатается прямо в промпте. Стоп
  записи на Windows — не SIGINT (его там нет), а `q` в stdin ffmpeg.
* Буфер обмена — `clipboard.js`: добавлена ветка `clip.exe` (Linux-ветка
  `xclip`/`xsel`/`wl-copy` не тронута).
* Уведомления — `notify.js`: на Windows `node-notifier` (toast), Linux
  как был — прямой `notify-send`.
* **Трей-иконка** (новое, не было в исходном плане — попросили при
  обсуждении этапа): `tray.js` на `systray2`, кроссплатформенно
  (Windows и Linux сразу, без разделения). Жёлтый — идёт
  запись/распознавание, зелёный — готов/предыдущий результат уже в
  буфере. Иконки — сплошной PNG/ICO, генерируются на лету (`icon.js`),
  без внешних файлов.
* Два реальных бага апстрима, вскрытых и обойдённых по пути в
  `systray2`: (1) `fs.chmod(bin, '+x')` — шелловый синтаксис вместо
  числового режима, Node молча падает, бинарник трея остаётся без
  прав на выполнение — обходим, сами делаем `chmod 755` перед стартом;
  (2) двойной default-export при ESM/CJS-интеропе (`m.default.default`
  вместо `m.default`) — разворачиваем вручную.

**Проверено мной (не требует Windows):** трей стартует, переключает
жёлтый/зелёный, завершается без осиротевших процессов (Linux); генерация
PNG/ICO подтверждена независимо через PIL и `file`; `clipboard.js`/
`notify.js`/`transcribe.js`/`reconfig` — без регрессий на Linux-ветке
после рефакторинга.

**Не проверено, нужна реальная Windows-машина:** весь путь записи через
`ffmpeg`/dshow целиком, `clip.exe`, Windows-уведомления через
`node-notifier`, реально ли выглядит трей-иконка (а не только процесс
жив).

**Тест:** тот же сценарий, что на этапе 4, но на чистой Windows-машине —
push-to-talk → буфер обмена → уведомление → жёлтый/зелёный статус в
трее.
